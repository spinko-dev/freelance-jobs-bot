# Freelance Jobs Bot 🤖

Личный Telegram-бот, который фильтрует поток вакансий по фрилансу
(видеомонтаж, озвучка, AI-автоматизация, AI-creating, скрипты, чат-боты, QA,
копирайтинг, переводы, транскрибация) и доставляет **только релевантные** заказы
в личный чат. Работает 24/7 на VPS.

## Возможности

- **Telegram-каналы** — читает веб-версии публичных каналов `t.me/s/<name>`:
  без API-ключей и Telegram-сессии, находит **только новые посты** (точки отсчёта
  хранятся в базе и переживают перезапуски).
- **Connect** — обходит заданные разделы каталога заказов `connect.tg`,
  разбирает карточки заказов и их UUID.
- **Категоризатор** — относит каждую вакансию к одной из 10 категорий
  по словарю ключевых слов (`config.py`). Мусорные посты («подработка Ozon»,
  промо-каналы, розыгрыши) в очередь не попадают.
- **Очередь + доставка** — новая вакансия попадает в SQLite-очередь; процесс-бот
  (long polling Telegram Bot API) отправляет её владельцу с категорией и ссылкой.
- **Настройки в боте** — владелец включает/выключает категории через inline-кнопки.
- **Дедупликация** — таблица `seen` в SQLite: каждая вакансия доставляется ровно один раз.

## Архитектура

```
                     ┌──────────────────┐
 t.me/s/<channels> ─►│   webparser.py   │───┐
 connect.tg/orders ─►│ connectparser.py │───┤   categorizer.py (10 категорий)
                     └──────────────────┘   ▼
                                       SQLite (queue / seen / settings)
                                            │
                                            ▼
                                     ┌────────────────┐
                                     │     bot.py     │──► Telegram
                                     │ (long polling) │
                                     └────────────────┘
```

- Два независимых процесса (systemd-сервисы): парсер и бот не блокируют друг друга.
- Отказоустойчивость: `Restart=always` — процесс сам поднимается, автозапуск при
  перезагрузке сервера.
- Сеть: опциональный прокси через `PROXY_URL`; на зарубежном VPS не нужен.

## Стек

- **Python 3.12**, **httpx** (HTTP-клиент), **SQLite** (стандартная библиотека)
- **Telegram Bot API** на «голом» long polling — без фреймворков
- **systemd** — автозапуск на Linux (на Windows — Планировщик задач)

## Быстрый старт

```bash
pip install -r requirements.txt
copy .env.example .env     # Windows; в Linux: cp .env.example .env
                            # заполните: BOT_TOKEN, SOURCE_CHATS
python webparser.py        # парсер (первый круг фиксирует точки отсчёта)
python bot.py              # бот-доставщик
```

## Деплой на VPS

1. VPS с Ubuntu 24.04 в не-РФ локации (тогда `t.me` и `api.telegram.org` открыты
   без прокси).
2. Файлы проекта → `/opt/freelance_jobs_bot`, создать venv:
   `python3 -m venv venv && venv/bin/pip install -r requirements.txt`.
3. Установить systemd-сервисы:

```bash
cp vps/*.service /etc/systemd/system/
systemctl daemon-reload
systemctl enable --now freelance-webparser freelance-bot
```

Дальше система живёт сама: перезагрузка сервера, падение процесса — всё
поднимается автоматически.

## Основные файлы

| Файл | Назначение |
|---|---|
| `webparser.py` | Цикл опроса каналов `t.me/s/*` и connect.tg, определение новых постов |
| `connectparser.py` | Парсер карточек заказов connect.tg по разделам |
| `categorizer.py` | Словарь-фильтр: категория вакансии или отсев мусора |
| `bot.py` | Доставка из очереди в Telegram, inline-меню настроек |
| `db.py` | SQLite-слой: очередь, seen, настройки |
| `config.py` | Конфигурация (категории, ключевые слова, каналы) |
| `diag_sources.py` | Диагностика: очередь по источникам + живость каналов |
| `vps/*.service` | systemd-юниты для VPS |

## Заметки

- `.env` (токен бота) и `data.db` (личные настройки/история) в репозиторий
  **не входят** — смотрите `.env.example` как образец.
- SQLite вместо Postgres/Redis выбрано сознательно: для single-host личного
  бота это один файл, который легко бэкапить целиком.
